# 5c 自动玩家状态与命名存档

基于 5b 的看 / 改布局继续开发。无需包提供 Easy See 元数据；本轮不读取 `state.json`，不提供游戏内采集包。

## 使用

1. 导入附加包，主动启动脚本，触发一个动作。打开顶部“玩家状态”。
2. 默认只列本次动作访问的存储项；初始化、其他动作和常驻定时器的记录留在“全部已知存储项”。数字、布尔、JSON 字符串、标签、分数、背包格子可编辑。源码位置、最近读写及次数可展开查看。
3. 修改后重新加载入口并触发最近的根动作，不重放领取等按钮历史。脚本模块缓存也会更新。若重开将改变存储，试运行写入不提交，清空旧画面并说明需要手动触发；显式触发和点击按正常脚本逻辑执行。
4. 展开“玩家存档”，输入名称保存。底部下拉框加载所选存档，当前工作状态与保存版本分开；修改不会悄悄覆盖已命名的版本。
5. 导出编辑器工程，下次可恢复工作状态、命名存档、记录和缩略图缓存。也能单独导出 / 导入玩家存档 JSON。普通资源导出排除 `.easysee/`。刷新网页前必须导出，尚未实现自动本地持久化。

武破方穹验证路径：右键古旧的羊皮卷，完成三步引导，再打开任务书。在玩家状态中编辑 `martial_realm` 为 `18`，任务书节点由未达成变为可领取；保存为“开阳圆满”。把境界改回 `0` 保存为“凡人”，底部切换两份存档，节点状态随之切换。中文“境界”命名及完整境界选项属于 5d；5c 只展示可从实际访问和源码推断的键、类型及选项。

## 实现边界

| 模块 | 职责 |
| --- | --- |
| `script-engine.js` | 模拟存储的读取、写入、来源、动作范围、时钟与快照 |
| `state-observer.js` | Babel 插桩，观察默认值、字面量比较、switch 和数组索引；不装箱、替换原始值 |
| `player-fields.js` / `player-state-panel.js` | 合并已知记录、推断输入类型、结构化 JSON 编辑和状态抽屉 |
| `player-saves.js` | 校验及规范化状态、不可变补丁、命名版本、工作副本和 sidecar |
| `player-session.js` | 重开动作的存储变化检查、限量缩略图路径探测 |
| `player-previews.js` | 独立 Worker 预览、源码 / 状态缓存键、首页和侧栏数据适配 |

存储覆盖玩家 / 世界动态属性、计分板、标签、36 格背包及物品名称 / lore / 动态属性、维度、虚拟 tick。动态属性遵循数字、文本、布尔和坐标对象类型；JSON 对象仍以脚本原来的字符串格式存储。高级 JSON 可补充未访问的键。导入先完整校验再提交，失败保留原状态。

枚举推断只使用有明确数据来源的比较、switch 或有限数组索引，不根据键名猜业务。复杂函数间的数据流、计算后的枚举和所有可能分支不能完整静态推导；手动输入仍保留。源码位置优先使用插桩位置，未覆盖的调用栈位置可能为近似位置。

自动重开只检查本模拟器可保存的存储是否发生变化；并不模拟真实世界回滚。会额外写入的动作需要手动触发，不能承诺所有脚本都能无副作用刷新。未模拟的世界 API、实体和结构等仍沿用 5a 的诊断与近似行为。

缩略图另开隔离运行器，不操作当前玩家。每次最多 12 个候选动作、32 条路径、3 层、每层前 10 个按钮；会改变存储的按钮响应不当作导航继续深入。每条路径从同一状态开始，包含 20 tick 的 HUD 观察。缓存绑定入口、脚本源码和当前状态，失配时不用旧结果；未探测到的分支显示说明。没有采集全部游戏分支，也不会虚构未访问界面的进度。播放时不逐 tick 重建整列，暂停后更新。

## 验证

```sh
npm test
npm run test:player-state
npm run test:player-state -- /path/reference.mcaddon /path/server_form.json /path/vanilla.zip
```

浏览器回归需要本地服务及 CDP 9222 的 Chromium。独立测试包不含 `state.json`，覆盖数字 / 枚举 / 布尔 / JSON / 标签 / 计分 / 背包、按动作筛选、自动刷新、领取不重复、非幂等动作拦截、双存档、缩略图像素变化、工程往返、无效状态保护和资源导出排除 sidecar。参考包覆盖 157 个模块、实际任务书 `martial_realm` 0 → 18、A → R 和存档切换。附加包不随仓库分发。
